# Arrays in Java 📦

> "Understanding the data structure first — its core properties and internal workings — before touching problems."

This section covers the fundamental properties, memory mechanics, and basic operations of Arrays in Java. 

## 🧠 Core Properties
An array is a foundational data structure characterized by a few strict rules:

*   **Fixed Length:** Arrays are a data structure of fixed length, meaning their size is restricted once created.
*   **Homogeneous Collection:** They can only store elements of the same data type.
*   **Continuous Memory Allocation:** Elements are stored in contiguous memory blocks, which is the secret behind their fast access times.
*   **Zero-Indexed:** From a developer's point of view, an array is index-based starting at 0, while from a user's point of view, it is position-based. Therefore, `Index = Position - 1`.

## ☕ Java-Specific Behaviors
While arrays exist in almost all languages, Java handles them with a few specific quirks:
*   **They are Objects:** In Java, an array is an object, with a real runtime class generated by the JVM (e.g. `int[].class`). It extends `Object` and inherits methods like `.clone()` and `.equals()` (reference equality by default). What you *can't* do is subclass an array type or write your own class definition for one — but at runtime, it behaves like any other object living on the Heap.
*   **Memory Location:** The array variable is a reference present in the Stack that points to the actual array stored in the Heap.
*   **Pass by Value (not Reference):** Java is technically **always pass-by-value** — this includes arrays and objects. What actually gets passed to a method is a *copy of the reference* (the memory address), not the original reference itself. Both the original variable and the method's parameter now point to the same array in the Heap, so mutations made through either one are visible to both. But if you *reassign* the parameter inside the method (e.g. `arr = new int[]{1,2,3}`), that only repoints the local copy — the caller's original array is untouched. This distinction matters a lot once you start reasoning about aliasing and memory ownership in systems-level code.
*   **Default Values:** When initialized without specific values, array elements are populated with the default value of their respective data type (e.g., `0` for integers).
*   **Aliasing vs. Copying:** These are two different things, and conflating them is a classic source of bugs.
    *   **Aliasing:** `int[] arr3 = arr;` does **not** create a copy — it just creates a second reference pointing to the *same* array in the Heap. Mutating `arr3[0]` also mutates `arr[0]`, because there's only one array underneath.
    *   **Shallow Copy:** For primitive arrays, `Arrays.copyOf(arr, arr.length)` gives you a genuinely independent copy — changing the copy has no effect on the original. There's nothing "shallow" left to worry about here since primitives are stored by value.
    *   **Deep Copy:** The shallow-vs-deep distinction only becomes meaningful for arrays of *objects*. A shallow copy of an object array gives you a new array with fresh slots, but each slot still points to the *same* underlying objects as the original — mutating an object's internal state through either array affects both. A deep copy would additionally clone each object itself, so the two arrays share nothing.

## ⚙️ The Magic of O(1) Access
Why is accessing an array element so fast? It comes down to basic math. 

When you request `arr[index]`, the program doesn't traverse the array to find it. Instead, it uses a formula internally:
`Memory Address = (Base Address of arr) + (Data Type Size × index)`.

Because this formula is executed internally without invoking any loops or recursion, traversing is not done. The element is fetched directly using that calculated address, resulting in a time complexity of O(1) for indexing.

## 🏗️ Basic Operations & Complexity

| Operation | Description | Time Complexity |
| :--- | :--- | :--- |
| **Indexing** | Fetching an element directly by its index. | O(1) |
| **Traversal** | Visiting every element. Depends entirely on the array size (n). | O(n) |
| **Update (by index)** | Replacing a value at a known index position. | O(1) |
| **Update (by value)**| Searching for a specific value to update it requires checking index by index. | O(n) |
| **Insert** | Inserting a value while retaining existing data requires shifting subsequent elements. | O(n) |
| **Delete** | Direct deletion of memory is not possible; elements must be replaced or shifted, resulting in up to n-1 swaps in the worst case. | O(n) |

*Note: In all operations (update, delete), always check for a valid index first.*

## 🆚 Array vs. ArrayList
To overcome the fixed-size limitation of arrays, Java provides the `ArrayList` class:
*   **Implementation:** `ArrayList` is a class in the Collections framework that internally uses arrays.
*   **Data Types:** While primitive arrays can hold both primitives and classes, `ArrayList` can work with only objects.
*   **Dynamic Resizing:** Size is not given explicitly. When the internal array gets full, it automatically doubles the size in new memory and copies the first half to the new memory. 
*   **Time Complexity Shift:** Because resizing depends on input, the time complexity for inserting an element when full becomes O(n), compared to the strict O(1) of a fixed array (if the index is known).

## 🧩 Common Problem Patterns

*I will be exploring these in detail with brute-force to optimized solutions in the problem files, but here are the mental models for the core array patterns:*

*   **Fixed Sliding Window:** Imagine a fixed-length magnifying glass; you move it across the array and update what enters and exits the frame.
*   **Variable Sliding Window:** Think of a rubber band that expands to satisfy a specific condition, and shrinks to regain validity when the condition breaks.
*   **Two Pointers (Opposite Ends):** Like two people walking from both ends of the array, meeting in the middle, and comparing pairs along the way.
*   **Two Pointers (Same Direction / Slow-Fast):** A leader (fast pointer) explores ahead, while a follower (slow pointer) consolidates accepted elements behind.
*   **Prefix Sum:** Acts as a cumulative scoreboard. Precomputing totals allows you to find subarray sums rapidly by using differences.
